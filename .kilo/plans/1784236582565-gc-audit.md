# GC Allocation Audit Findings

Audit date: 2026-07-16

## Scope

Gameplay-critical paths: `Update()`, `Draw()`, collision detection, input handling, entity spawning/despawning, state machine transitions, AI updates, HUD rendering.

## Findings

### CRITICAL

#### GameLoop/GameLoop.cs:295 — `foreach` over `QueryCollisionPairs` (IEnumerable)

**Pattern:** Temp collection / enumerator allocation
**Code:** `foreach (var pair in _collisionWorld.QueryCollisionPairs("actors", "props"))` in `ResolveCollisions()`, called every frame during gameplay.
**Allocation:** `QueryCollisionPairs` returns `IEnumerable<CollisionPair>`, so `foreach` allocates a heap-enumerator object every frame.
**Fix:** Buffer the results into a pre-allocated `List<CollisionPair>` field. Call `.Clear()` then iterate with a `for` loop. Or use a `List<CollisionPair>` as the output parameter if the API supports it.

---

### HIGH

#### Combat/HitboxService.cs:94 — HashSet allocation per unique attack owner

**Pattern:** Temp collection allocation
**Code:** `ownerDedup = []; _attackDedup[active.Owner] = ownerDedup;` in `ResolveHits()`, called every frame during gameplay when there are active hitboxes.
**Allocation:** Allocates a new `HashSet<Entity>` per unique attacking entity on first hit per attack chain. Accumulates one HashSet per entity that has ever attacked.
**Fix:** Pool `HashSet<Entity>` instances (e.g., `Stack<HashSet<Entity>>` or custom `ObjectPool<HashSet<Entity>>`). Rent on first hit, return on `ClearAttackDedup`.

---

### MEDIUM

#### UI/PlayerBar.cs:32 — String allocation on lives change

**Pattern:** String allocation
**Code:** `_label = $"{_player.Name}  ={_player.Lives}";` in `Update()`, triggered when `_player.Lives` changes.
**Allocation:** Allocates a new string each time the player loses a life. Infrequent (once per death).
**Fix:** Acceptable — once per death is not a hot path. No change needed unless death rate becomes very high.

---

### LOW

#### GameLoop/GameLoop.cs:221 — Debug overlay string interpolation

**Pattern:** String allocation
**Code:** `Gum.DebugOverlay.SetText(...)` with multi-line string interpolation in `Draw()`, gated by `IsDebug`.
**Allocation:** Multiple strings allocated per frame when debug mode is active.
**Fix:** No change needed — debug-only path.

#### Entities/CombatActorBase.cs:116 — `ToDisplayString()` in DrawDebug

**Pattern:** String allocation
**Code:** `HealthComponent.ToDisplayString()` allocates `$"{Value}/{MaxHealth}"` per frame in debug mode.
**Allocation:** String allocation per entity per frame in debug mode.
**Fix:** No change needed — debug-only path.

---

### Needs Verification (potential findings)

#### Levels/LevelDirector.cs:162, 228, 258 — `foreach` over `wave.Enemies`

If `WaveDef.Enemies` returns `IReadOnlyList<EnemySpawnDef>` (interface), the `foreach` allocates an enumerator in `SpawnWave()` (per-wave) and `DrawDebug()` (debug-only). If it returns the concrete `List<EnemySpawnDef>`, C# generates a struct enumerator — no allocation.
**Check:** Inspect `WaveDef.Enemies` property return type.

## Sound Engine (New) — Separate Audit

### Files

- `MonoGameLearning.Core/Audio/AudioManager.cs`
- `MonoGameLearning.Core/Audio/SfxId.cs` (enum — no allocations)
- `MonoGameLearning.Core/Audio/MusicId.cs` (enum — no allocations)
- `MonoGameLearning.Core/Settings/AudioSettings.cs` (record — no hot path allocations)
- `MonoGameLearning.Core/Settings/SettingsData.cs` (record — no hot path allocations)

### Hot Paths Analyzed

**`AudioManager.Update(GameTime)`** — Called every frame in `GameLoop.Update()`.

- Null check on `_musicInstance`, then single `MusicId.LevelComplete` state check + `SoundState.Stopped` check.
- **No allocations.** Struct checks and null checks only.

**`AudioManager.PlaySfx(SfxId)`** — Called per-attack, per-hit, per-menu-nav (multiple times per frame during combat).

- Two `Dictionary.TryGetValue` lookups (struct keys, no boxing for enum keys in generic `Dictionary<K,V>`).
- `instance.Stop()` / `instance.Play()` — MonoGame API calls, no allocation.
- **No allocations.** Clean.

**`AudioManager.SetPaused(bool)`** — Called on pause/unpause state transitions.

- Sets `_isPaused`, calls `ApplyMusicVolume()` which sets `_musicInstance.Volume`.
- **No allocations.** Clean.

**`AudioManager.PlayMusic(MusicId?)`** — Called on game state transitions (title→playing, playing→pause, etc.).

- `_musicEffects.TryGetValue` — Dictionary lookup, no allocation.
- `effect.CreateInstance()` — Allocates a `SoundEffectInstance` object (MonoGame API, unavoidable). Only on state transitions, never per-frame.
- **One allocation per music start.** MEDIUM severity but unavoidable.

**Entity state callbacks** — `PlayerEntity`/`EnemyEntity` call `GameCore.Audio.PlaySfx(...)` in cached delegate closures.

- Delegates are created once in `CreateStateController()`, not per frame.
- `PlaySfx` is allocation-free as analyzed above.
- **No per-frame allocations.** Clean.

### Load / Cold Paths (Not Hot)

**`AudioManager.LoadContent(ContentManager)`** — Called once in `GameLoop.LoadContent()`.

- `LoadSfxGroup(params ...)` allocates a `(SfxId, string)[]` params array. One-time load, not a hot path.
- `Debug.WriteLine(...)` string interpolation in catch blocks — error-path only.

### Verdict

The sound engine introduces zero per-frame allocations. All gameplay-critical paths (`Update`, `PlaySfx`, `SetPaused`) are allocation-free. The only allocation in `PlayMusic` (`CreateInstance()`) is unavoidable and only occurs on game state transitions.

These were inspected and confirmed allocation-free:

- `EnemyAI.Update()` — struct math, indexed `for` loops over `IReadOnlyList<ActorSnapshot>`, no allocations
- `HitboxService` — pre-allocated `_resultBuffer` / `_boundsBuffer`, indexed `for` loops, struct types
- `EntityManager.ProcessPending()` — `foreach` over `List<Entity>` (struct enumerator)
- `LevelDirector.PopulateSnapshots()` — pre-allocated `_enemyBuf`/`_propBuf` with initial capacity, struct `ActorSnapshot`
- `PlayerEntity.Update()` / `EnemyEntity.Update()` — cached state machine delegates, no per-frame closures
- `CameraController.Update()` — pure struct math
- `Mover` — static methods, no allocations
- `EnemyBar.Render()` — string labels are pre-existing entity names, `MeasureString` caches
- `PlayerBar.Render()` — `_label` string is cached, reused until lives change
- `AnimationFrameTracker` — no allocations
- `CombatService.ApplyDamage()` — no allocations
- `FindNearestAliveEnemy()` — indexed `for` loop, no LINQ
