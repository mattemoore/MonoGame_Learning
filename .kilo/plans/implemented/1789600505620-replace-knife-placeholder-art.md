# Plan: Replace Knife Placeholder Art

> **Status:** Implemented (2026-09-17). Deviations from the sketch:
>
> 1. The art ships a **7-frame authored `Fly` run** (`knife-fly-00..06`, 32x32, 100ms/frame),
>    so the projectile plays it as a time-driven region run instead of a single static
>    region + code rotation. `ThrowableWeaponDef` gained
>    `ProjectileRegionPrefix`/`ProjectileFrameCount`/`ProjectileFrameDuration`/`ProjectileLoop`
>    (`ProjectileRegion` was replaced) and `ProjectileEntity` gained a flight-frame timer
>    (`FlightFrameIndex` exposed for debug/tests); `SpinDegreesPerSecond` is now `0`.
> 2. The converter prints **no** carry paste block for a throwable (its emitter needs both a
>    `hold` and a `swing` tag). The knife's carry offset was read directly from the `Handle`
>    slice (`bounds 12,21 + pivot 3,5` → `(15,26)`).
> 3. The new textures had to be copied into `Content/images/` by hand — the converter only
>    emits the atlas JSON.
>
> Hand tuning: `CarryHandAnchor` now points at the same player hand as the bat
> (`BatWeapon.CarryHandAnchor`); `WeaponScale = 0.5`, `ProjectileScale = 0.5`, and
> `SpawnOffset (18,-4)` are still first-pass values that need an in-game look.

## Goal

Swap the knife's one-frame placeholder art (`knife-texture.png` / `knife.json` /
`knife-pickup.png`, generated by `Utils/placeholder_gen.py`) for real Aseprite-authored
art, keeping the throwable pipeline intact. No gameplay change: the knife still one-shots
a 30-HP enemy (`Damage = 30`), spawns its projectile on `SpawnFrame = 1`, and spins in
flight.

## Current placeholder state (what we are replacing)

| Piece | Current value |
| --- | --- |
| Atlas texture | `Content/images/knife-texture.png`, 12x40, single region `knife-00` |
| Atlas JSON | `Content/images/knife.json`, `monogame-extended`, one region |
| Pickup icon | `Content/images/knife-pickup.png` (plain texture) |
| `KnifeSprite.FrameRegion` | `"knife-00"` (one region serves carry **and** projectile) |
| `KnifeWeapon.FrameCenter` | `(6, 20)` (region half-size — `RenderWeaponOverlay` asserts this) |
| `KnifeWeapon.CarryHandAnchor` | `(14, -4)` (actor-side hand anchor, no handle slice yet) |
| `CarryHandleOffset` | `(0, 0)` → `HasHandleOffsets == false` (region center sits on the hand) |
| `ProjectileRegion` / `ProjectileScale` | `knife-00` / `1f` |
| `SpawnOffset` | `(20, -4)` (actor units, mirrored by facing) |

Facts that constrain the swap:

- The projectile is **region-keyed and rotated**, never frame-stepped: `ProjectileEntity.Draw`
  draws `ThrowableWeaponDef.ResolveProjectileRegion()` once per frame and spins it via
  `SpinDegreesPerSecond`. So the flying knife needs a **single** region — no animation tag
  required for flight.
- The carry pose is region-keyed too: `WeaponDef.ResolveCarryRegion()` looks up `CarryRegion`
  by name. Carry and projectile **may** be different regions (currently they share one).
- `FrameCenter` must equal the resolved region's half-size or the Debug grip assertion in
  `RenderWeaponOverlay` fires. Carry and projectile regions should therefore share a size
  (or the projectile resize must be folded into `ProjectileScale`).
- `SpriteSheetAsset` may load an atlas with zero animation defs (current knife), or with
  tag-derived runs if the new export has `frameTags`.
- `dotnet build` does **not** validate that JSON frame rectangles fit the texture — only a
  live run confirms alignment.

## Authoring brief for the new art (user, before resuming)

Author under `MonoGameLearning.Game/Sources/Weapons/Knife/`:

1. `knife.aseprite` with the knife drawn at a readable size (e.g. 16x48 or 24x24) and, if
   the carry pose differs from the flying pose, one of:
   - two frame tags (e.g. `hold`, `fly`) — one frame each, or
   - a single untagged frame reused for both.
2. A slice named **`handle`** (lowercase), pivot enabled, one key on the grip pixel, if the
   grip should not sit at the region center. Export with **Slices** checked so the converter
   can print fresh `CarryHandleOffset` values.
3. Export Sprite Sheet → `knife.json` + `knife-texture.png` (JSON Array or JSON Hash). Copy
   `knife-texture.png` into `Content/images/` (or let the converter place it).
4. Draw a matching `knife-pickup.png` icon (roughly 16x16) at `Content/images/knife-pickup.png`.
5. Optionally set `ProjectileScale` expectations: the drawn flying region is scaled by
   `actorScale * ProjectileScale`, spun at 720°/s.

## Steps (assistant, when the user resumes with art ready)

1. **Convert the export** into the content atlas:

   ```bash
   python3 Utils/aseprite_to_monogame_extended.py \
     Sources/Weapons/Knife/knife.json --name knife \
     --out-dir MonoGameLearning.Game/Content/images
   ```

   Read the printed block: `SpriteAnimationDef` lines (if tagged), and
   `CarryHandleOffset` / `SwingHandleOffsets` (paste the carry value; ignore swing — the
   knife is a throwable and has no swing run).

2. **Verify the atlas** `Content/images/knife.json`: `dataformat: monogame-extended`,
   region names match the tag/untagged naming (`knife-hold-00` / `knife-fly-00` or
   `knife-frame-00`), and the referenced texture matches the JSON size. Copy the source
   texture over `Content/images/knife-texture.png` if the converter did not.

3. **Update `KnifeSprite.cs`**: set region name constants to the new names. Split
   `FrameRegion` into `CarryRegion` / `ProjectileRegion` when the two poses differ, and add
   a `SpriteAnimationDef` only if the export carried a tag the sprite must step (the
   projector does not frame-step, so this is usually unneeded).

4. **Update `KnifeWeapon.cs`**:
   - `FrameCenter = region size / 2`.
   - `CarryHandleOffset` = converter output; `CarryAnchor = CarryHandAnchor - (CarryHandleOffset - FrameCenter) * Scale`.
     Keep `CarryHandAnchor` hand-tuned and re-check it in-game.
   - `CarryRegion` / `ProjectileRegion` = new sprite constants.
   - `ProjectileScale` if the flying region is drawn at a different size.
   - `SpawnOffset` re-tuned so the knife leaves the hand, not inside it.

5. **Content pipeline**: no `Content.mgcb` changes if filenames are unchanged; if a file is
   renamed, mirror the `images/knife*` block (`Content.mgcb:106-133`).

6. **Tests**: property-based knife tests (`ThrowableWeaponTests`) should still pass. Grep
   for literal region names / sizes in tests before running; update any that pin the old
   `knife-00` name or `(6, 20)` center.

7. **Docs**: update `MANUAL_TESTING.md` rows 3.8–3.10 / 7.15–7.19 only if the visual
   expectations change (e.g. pickup icon look, spin look). Update `AGENTS.md` /
   `LEARNING.md` only if the art pipeline itself changed (it should not).

8. **Verify**:

   ```bash
   dotnet build --warnaserror
   dotnet test
   ```

   Then a live run: pick up the knife (x≈250), confirm the held pose sits on the hand,
   Attack1 throws it, the flying region is correct and spins, facing-left mirrors, the
   dropped pickup icon is the new `knife-pickup.png`, and the projectile still one-shots an
   enemy. Run the markdown linter on any `.md` touched.

## Risks / gotchas

- `RenderWeaponOverlay` Debug-asserts `region half-size == FrameCenter`; a mismatched new
  region size crashes only in Debug, silently offsets the grip in Release.
- The converter's handle-slice output is only as good as the Aseprite slice: without a
  `handle` slice the anchors stay region-center and must be hand-tuned.
- Keep the atlas to a single texture or the `TexturePackerProcessor` import path breaks.
- Do not reintroduce per-frame `SetFrame`/`TextureRegion` syncing for the projectile; the
  spin is a Draw-time rotation by design.
